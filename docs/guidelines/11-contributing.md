# Как развивать систему

## Когда нужен новый компонент

- Один и тот же элемент свёрстан на двух сайтах или дважды на одном.
- Сайту нужно «как компонент, но немного иначе» — сначала проверьте, не проп ли это существующего.
- Доменные вещи (колонка доски, ценник Ленты, узел карты зависимостей) в систему не идут — они собираются на сайте из компонентов.

## API

| Правило | Пример |
|---|---|
| смысловой цвет — `tone` | `Tag tone="ok"`, `Stat tone="warn"` |
| вид кнопочных элементов — `variant` | `Button variant="ghost"` |
| размер — `size`: `sm`/`md`/`lg` | `Chip size="sm"` |
| доступное имя — `label` | `Switch label="Свет"` |
| смена значения — `value` + `onChange(value)` | `onChange` отдаёт значение, не событие |
| у каждого компонента — `className` | тест проверяет все `*Props` |
| булевы — без `is`/`has` | `loading`, `dimmed`, `block` |
| устаревший проп — `/** @deprecated … */` и новое имя рядом | `Segment ariaLabel` → `label` |

## Стили

- Файл на компонент: `Name.tsx` + `Name.css`, импорт в `src/styles.css`.
- Классы по БЭМ с префиксом: `.vs-name`, `.vs-name__part`, `.vs-name--modifier`.
- Только токены: без px/rem вне `calc(Npx * var(--vs-scale, 1))`, без hex/rgb, чисел в `z-index`, длительностях, тенях. Исключения — ширина рамки и обводки, `@media`, запасные `0px` у переменных Base UI.
- Киоск и модификаторы — через переменные компонента (`--vs-name-*`). Никаких `.vs-kiosk .vs-name`.
- Фокус — `outline: var(--vs-focus-ring)`; наведение — `@media (hover: hover)` и `--vs-hover`.
- Сложные виджеты (меню, списки выбора, диалоги, шторки) — на Base UI под своей обёрткой; сайты Base UI напрямую не трогают.

## Тесты

- Поведение — тест компонента в `tests/` (роль, `aria-*`, события).
- Сторожа в `tests/tokens.test.ts` и `tests/api-guidelines.test.tsx` срабатывают сами — не ослабляйте их ради нового кода.
- Каталог: у компонента есть `docs/components/Name.md` и `showcase/stories/Name.tsx` — тест покрытия падает, если их нет.
- Перед влитием — попиксельное сравнение каталога до и после, если меняли существующие стили.

## Релиз и раскатка

1. PR в `asdasd-dev/vshome-ui` с версией в `package.json` (минор — новое, патч — правка).
2. После влития `deploy.sh`: тесты → сборка → тег `vX.Y.Z` → раскатка: PR в каждый сайт из `consumers.json`, при зелёных тестах вливается сам.
3. Каталог на `vshome.space/ui/` обновляется той же выкаткой.

## Вывод из употребления

Пометка `@deprecated` → сайты переводятся раскаткой или отдельным PR → удаление в следующем мажоре или когда в сайтах не осталось использований (поиск по `consumers.json`).

## Чек-лист ревью

- [ ] Нет литералов, все цвета и размеры — токены
- [ ] Есть фокус и наведение у интерактивного
- [ ] `className`, `label` у управляющих, `onChange(value)`
- [ ] Работает в светлой, тёмной и в `.vs-kiosk`
- [ ] Страница в `docs/components` и примеры в `showcase/stories`
- [ ] Тесты на поведение, сторожа зелёные
- [ ] Каталог до/после сравнён, если трогали старое
